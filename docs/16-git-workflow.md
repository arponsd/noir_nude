# 16 — Git Workflow

Owner: orchestrator + `devops` agent. All contributors (human and agent) follow this file exactly.

## Repo model

- **Hosting:** GitHub.
- **Default branch:** `main`.
- **Integration branch:** `develop`.
- **Linear history on `main`.** Squash-merge only. No direct pushes.
- **No force-push** on `main` or `develop` — ever.
- **Signed commits** required (`commit.gpgsign=true` or SSH signing).

## Branches

| Branch                          | Purpose                    | Deployed to    | Protection                                    |
| ------------------------------- | -------------------------- | -------------- | --------------------------------------------- |
| `main`                          | Production-ready           | production     | Protected: 1 review, green CI, signed, linear |
| `develop`                       | Integration                | staging        | Protected: 1 review, green CI                 |
| `feat/<agent>-<scope>-<short>`  | New feature                | preview per-PR | —                                             |
| `fix/<agent>-<scope>-<short>`   | Bug fix                    | preview per-PR | —                                             |
| `chore/<agent>-<scope>-<short>` | Tooling / docs / deps      | preview per-PR | —                                             |
| `hotfix/<scope>-<short>`        | Urgent prod fix off `main` | preview + prod | 1 review, green CI                            |
| `release/<version>`             | Release stabilization      | staging        | 1 review                                      |

Agent prefix identifies the lane: `frontend`, `backend`, `database`, `security`, `devops`, `qa`. Example: `feat/frontend-pdp-shade-selector`, `fix/backend-cart-empty-coupon`.

Branches are short-lived. Target: merge within 3 days. Rebase on `develop` weekly; delete after merge.

## Commits

**Conventional Commits** enforced by `commitlint`.

```
<type>(<scope>): <short summary>   ≤72 chars, imperative

<body — optional, wrap at 72 chars>

<footer — optional: BREAKING CHANGE, Refs #123, Co-Authored-By>
```

| Type       | When                        |
| ---------- | --------------------------- |
| `feat`     | New user-visible capability |
| `fix`      | Bug fix                     |
| `refactor` | No behavior change          |
| `perf`     | Performance-only            |
| `test`     | Tests only                  |
| `docs`     | Docs only                   |
| `chore`    | Tooling, deps, non-code     |
| `build`    | Build system / config       |
| `ci`       | CI config                   |
| `style`    | Formatting only (rare)      |
| `revert`   | Revert a prior commit       |

**Scope** = lane + domain: `frontend/pdp`, `backend/cart`, `database/product`, `security/csrf`, `devops/ci`, `qa/e2e`.

Examples:

```
feat(frontend/pdp): shade selector with swatch previews
fix(backend/cart): validate coupon against current cart items
chore(devops/ci): cache pnpm store between runs
```

Breaking change:

```
feat(backend/order)!: rename orderStatus `confirmed` → `placed`

BREAKING CHANGE: Clients must map `confirmed` to `placed` during migration window.
```

## Pull requests

### Naming

PR title = first commit subject after squash: `<type>(<scope>): <short>`.

### Description template

Auto-populated from `.github/PULL_REQUEST_TEMPLATE.md`. Must fill:

- **What** — one paragraph.
- **Why** — link to task card / contract section.
- **How** — brief technical notes when non-obvious.
- **Test plan** — checklist.
- **Screenshots** — UI changes.
- **Bundle delta** — frontend tasks.
- **Agent lane** — which of the 6 agents owns this.
- **Blast radius** — files, migrations, cross-lane impacts.

### Required checks before merge

| Target branch       | Required checks                                       |
| ------------------- | ----------------------------------------------------- |
| feature → `develop` | typecheck · lint · unit · integration · bundle-budget |
| `develop` → `main`  | all above + e2e-smoke · audit-high                    |
| hotfix → `main`     | all above + sign-off from orchestrator                |

### Review policy

- 1 required review from another agent lane (cross-lane eyes catch contract drift).
- `CODEOWNERS` auto-assigns reviewers based on touched paths.
- Changes to `docs/04-contracts.md` require orchestrator approval.
- Changes to `package.json` / `tsconfig.json` / `constants.ts` require ping in all-agent chat before merge.

### Merge strategy

- **Squash and merge** into `develop` and `main`. Rebase-and-merge only for release branches.
- Merge commit message = PR title + body auto-generated by GitHub.
- Never merge red CI. Never merge with unresolved review threads.

### Stacked PRs

When a feature needs cross-lane work, stack PRs with `Depends on #123` in the description. GitHub's "merge queue" (enabled on `develop`) orders them.

## Release flow

1. Cut `release/v1.X` off `develop` when phase milestones close.
2. QA runs full e2e + a11y + Lighthouse on the preview.
3. Tag `v1.X.0`, generate changelog with `changesets` (devops owns config).
4. Merge `release/*` → `main` with **merge commit** (preserve release history).
5. Back-merge `main` → `develop` same day.
6. Auto-deploy to production on `main`.

## Hotfix flow

1. Branch `hotfix/<slug>` off `main`.
2. Fix + test.
3. Merge to `main` (squash), auto-deploy.
4. Back-merge `main` → `develop`.
5. Postmortem under `docs/postmortems/<YYYY-MM-DD>-<slug>.md` within 48h if user-visible.

## Multi-agent coordination

### Task-first, branch-second

Every branch traces to a task card (issue with `task` label). Branch name embeds the issue number:

```
feat/frontend-cart-drawer-#142
```

Close the issue automatically via `Closes #142` in the PR body.

### Cross-lane locks

When two agents will touch a shared file (e.g., `src/types/api/order.ts`):

1. The lane that needs the **new symbol** goes first.
2. File an issue `lock/<file>` assigned to both lanes; second lane waits.
3. After merge, second lane rebases and proceeds.
4. Remove the lock issue.

### Conflict resolution

- **File conflict on rebase:** the later-merging agent resolves. If ambiguous, ping orchestrator.
- **Semantic conflict** (tests pass, behavior wrong): owner of the _contract_ file (`docs/04-contracts.md`) decides.
- **Never** `git push --force` to a shared branch. Use `--force-with-lease` on your own feature branch only.

### Agent identity in commits

Each agent signs its commits with a distinct trailer:

```
Co-Authored-By: Agent-Frontend <frontend@cosmetic.local>
```

Enables `git log --author` audits of lane activity.

## Pre-commit hooks (Husky)

`.husky/pre-commit`:

- `lint-staged` runs Prettier + ESLint on staged files.
- `typecheck` on files that changed (`tsc --noEmit` on the changed packages — fast with project refs).

`.husky/commit-msg`:

- `commitlint` validates format.

`.husky/pre-push`:

- `pnpm test:unit` smoke run.

**Never skip hooks with `--no-verify`.** If a hook fails, fix the cause.

## `.gitignore` highlights

See the file itself — includes: `node_modules/`, `.next/`, `coverage/`, `.env*` (except `.env.example`), `*.log`, `.vercel/`, `playwright-report/`, `test-results/`, `.DS_Store`, `Thumbs.db`.

## `.gitattributes`

- Line endings: `* text=auto eol=lf`.
- Binary detection for `*.png *.jpg *.webp *.pdf *.woff2`.
- Exclude `tests/fixtures/**` from language stats (linguist-generated).

## Secrets & PII

- **Never** commit `.env*` except `.env.example`.
- **Never** commit Cloudinary signatures, Resend keys, MongoDB URIs, Sentry tokens.
- Pre-push hook runs `gitleaks` (or `trufflehog`) scan.
- If a secret leaks: rotate first, then `git filter-repo` to purge history, then force-push `main` with orchestrator approval and user sign-off. Log the incident in `docs/postmortems/`.

## Tags & versions

- SemVer: `vMAJOR.MINOR.PATCH`.
- MAJOR bump = breaking change in API contract (`docs/06-api-contract.md`) or DB schema migration required for clients.
- MINOR = new feature, backward compatible.
- PATCH = fix.
- Tags signed (`git tag -s`).
- Release notes generated from Conventional Commits via changesets.

## Dependabot / Renovate

- Weekly PR batch, `chore(deps):` prefix.
- Auto-merge patch updates if CI green (devops agent only).
- Minor/major updates require lane-owner review (changes to UI libs → frontend; DB driver → database; etc.).

## Local setup for new agents

```bash
git clone <repo>
cd cosmetic-ecommerce
pnpm install
pnpm run prepare          # installs Husky
cp .env.example .env.local
# populate .env.local from Vercel pull or shared vault
pnpm dev
```

## Forbidden actions (enforced by CODEOWNERS + branch rules)

- Direct push to `main` or `develop`.
- Force-push to shared branches.
- Committing with `--no-verify`.
- Editing `docs/04-contracts.md` without orchestrator review.
- Editing outside your agent lane without an approved cross-lane PR.
- `git init` in a subdirectory.
- Rewriting published history.
